The `challenge1.exe` binary was executed, which displayed the following prompt as shown on left image. Upon clicking the **DECODE!** button, the interface changed as shown on right image.

![Clicking Decode](/images/2025-01-18-Flare-On-2014-C1/1.png)

For initial analysis, the binary was loaded in **PeStudio**, where it was written in `C#` using `.NET` framework.

![.NET framework](/images/2025-01-18-Flare-On-2014-C1/2.png)

Given its .NET origin, the binary was then loaded in **dnSpy** for de-compilation. In dnSpy, following path was traced: 
`Main()` > `Form1()` > `InitializeComponent()` > `btnDecode_Click()`

The `btnDecode_Click()` method contained code that retrieve data from the `dat_secret` resource and perform some operations on it. To quickly get the final result of these operations, a breakpoint was set at the end of the method. Upon execution, the breakpoint revealed the flag for this challenge as shown below. 

![Flag](/images/2025-01-18-Flare-On-2014-C1/3.png)

Note that the first loop decrypts the flag and stored it in the `text` variable, while other subsequent two loops seems to make the flag gibberish. The value stored on `text3` is what we seen when clicking the **DECODE!** button.

Lets replicate the first loop in python. First, the `dat_secret` resource was saved as:

![Saving resource](/images/2025-01-18-Flare-On-2014-C1/4.png)

The saved resource `dat_secret` content can be seen below.

![Resource content](/images/2025-01-18-Flare-On-2014-C1/5.png)

The following python script replicates the first loop and decrypts the final flag.

```python
cipher_text =  bytes.fromhex("A1B5448414E4A1B5D470B491B470D491E4C496F45484B5C440647470A46444")
plain_text =  ""
    
for text in cipher_text:
	plain_text +=  chr(((text >>  4) | ((text <<  4) &  0xF0)) ^  41)
print(plain_text)
```

**Flag:** `3rmahg3rd.b0b.d0ge@flare-on.com`
